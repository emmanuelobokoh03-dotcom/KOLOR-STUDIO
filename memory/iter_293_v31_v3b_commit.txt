Workstream 4 (bundled): Revenue endpoint optimization
------------------------------------------------------
Prior state: getRevenueStats ran 13 sequential queries
(4 aggregates + 12-loop for monthlyTrend). Classic N+1.

Changes (backend/src/services/crm.ts):
- Parallelized 4 top-level aggregates + swapped monthlyTrend loop for
  a single findMany scanning the 12-month window, then in-memory
  bucketing → 13 sequential queries → 5 parallel queries
- Added helper buildMonthlyTrendFromRows(rows, months) — same output
  shape, no callsite change
- Preserved legacy getMonthlyTrend for external callers (referenced
  via `void getMonthlyTrend` for TSC)

Prisma schema:
- Added @@index([userId, status, receivedDate]) on Income model —
  supports the aggregate WHERE clauses AND the findMany trend scan
- Applied via prisma db push

Expected impact: ~5-10× reduction in DB round-trips for GET
/api/crm/revenue (Railway → Supabase pooler latency dominant).
Powers RevenueHero on Today page + RevenueDetailModal + existing
RevenueDashboard when opened.
